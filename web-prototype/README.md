# ape-dts Console · Web Prototype

A high-fidelity web management console prototype for the **ape-dts** data sync
engine, shipped under the open-source brand **ape-dts Console**. Built with
Vue 3 + TypeScript + Element Plus + ECharts + Tailwind + Pinia + MSW, running
entirely in the browser with mocked data (no backend required).

## Quick start

```bash
cd web-prototype
pnpm install
pnpm msw:init      # first-time only — generates public/mockServiceWorker.js
pnpm dev           # http://127.0.0.1:5173
```

Default demo credential: **`admin` / `admin123`** (any non-empty credential works).

## Mock vs real backend

MSW is gated behind the `VITE_USE_MOCK` flag (Vite env var). The committed
`.env.development` sets it to `true`, so `pnpm dev` runs offline with the
in-memory mock DB out of the box. To point the SPA at a real orchestrator:

```bash
# one-shot override (highest precedence)
VITE_USE_MOCK=false pnpm dev

# or persist locally (gitignored)
echo "VITE_USE_MOCK=false" > .env.development.local
```

For production: leave `VITE_USE_MOCK` unset (the default), or copy
`.env.production.example` to `.env.production` and set `VITE_USE_MOCK=false`.
The mock layer (`src/mock/**` + `msw`) is dynamically imported behind the flag
and tree-shaken out of bundles where the flag isn't `true`.

## Production deployment

The router runs in HTML5 `history` mode (no `#/` in URLs), so any web server
that hosts the built `dist/` must fall back to `index.html` for unknown paths
(deep-link refresh, copy-paste URL). Minimal nginx config:

```nginx
server {
  listen 80;
  root /var/www/ape-dts-console/dist;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    proxy_pass http://127.0.0.1:8080;   # ape-dts orchestrator
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;                # required for SSE (logs / alerts)
    proxy_read_timeout 1h;
  }
}
```

Vite's dev server already handles SPA fallback automatically; no extra config
is required for `pnpm dev`.

## Design baseline

- **Visual**: D2 — Linear/Vercel enterprise light; deep-teal primary (`#0F766E`), near-white canvas (`#F8FAFC`), 6-8px radii, single-layer soft shadows.
- **Layout**: Collapsible left sidebar (224 / 64 px) + fixed top bar (56 px) + PageHeader + trailing footer.
- **i18n**: zh-CN filled, en-US scaffolded; locale switcher in top bar and login.
- **Mock**: MSW intercepts `/api/*` with a mutable in-memory DB, 300-900 ms random latency and 5% failure injection.

## Design decisions (frozen)

See chat log for the 12-question grill session that locked these. Summary:

1. Vue 3 + Element Plus + ECharts + Vite + Tailwind + Pinia + MSW
2. ape-dts Console brand (no Huawei), deep-teal palette, geometric mark
3. D2 Linear/Vercel visual language with explicit design tokens
4. 26 pages P0/P1/P2
5. Collapsible sidebar, no global search, module order preserved
6. i18n L2 (zh-CN full, en-US scaffold)
7. 7-step sync creation wizard + entry modal + edit drawer + INI preview
8. Soft gating + differentiated per-step validation + localStorage draft + submit-to-detail loop
9. MSW + Pinia + realistic seeded data + 5 s polling realism
10. Dashboard: banner + 4 KPI + 2-col time series + 3-col distribution + 2-col recent
11. Task detail: 6 tabs + persistent action bar; alert-monitor = config center (not chart center)

## Demo script (P0 happy path)

1. Land on `/login`, click **Sign in** (pre-filled `admin / admin123`).
2. Dashboard — view global KPIs; click a status wedge to jump filtered list.
3. `+ 创建任务` → type picker modal → Sync task → 7-step wizard.
4. Fill, validate, test connection, pick migration objects, add Lua transform, run precheck, preview INI, submit.
5. Auto-jump to task detail; watch real-time metrics scroll; open log tab.
6. Back to alerts — click an alert row → jump back to the related task's 告警绑定 tab.

## Cross-module linkage tour (verifying P1/P2)

1. Dashboard "今日告警" KPI → `/alerts/current`; the current-alerts page picks up the implicit "all levels" filter and starts auto-refreshing every 8 s.
2. Click any alert row → `/tasks/{cat}/{taskId}?tab=alerts`; the task detail jumps directly to the 告警 tab.
3. From the alerts tab click 编辑 → drawer opens via `?edit=1` deep link.
4. In OpsManagement → switch tabs to verify all three categories share the same TaskListView shell with isolated polling.
5. Open MetricRules → create a rule → toggle row switch → confirm the in-memory mock store persists across page reloads (until full browser reload).
6. AlarmSetting → click 测试连接 on a Kafka channel → see deterministic 85% success / 15% failure path.
7. License page → click 激活 / 续期 → enter any code ≥ 8 chars → success toast; the global LicenseBanner re-fetches on next page mount.
